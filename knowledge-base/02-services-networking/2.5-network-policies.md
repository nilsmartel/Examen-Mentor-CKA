# 2.5 — Network Policies

**Domain:** Services & Networking (20%) · **Lab:** `labs/lab-2.5-network-policies.md`
**Prereqs:** [[2.2-services-endpoints]]. Needs a policy-enforcing CNI (Calico/Cilium).

## Learning objectives
The student can: write ingress/egress NetworkPolicies, reason about additive (OR) rules, and implement
a default-deny posture.

## Teaching notes

**Default = wide open.** Without any NetworkPolicy, all pods can talk to all pods. A NetworkPolicy
**restricts** traffic for the pods it selects. **A CNI that enforces policy is required** — plain
Flannel ignores them; Calico/Cilium enforce. (On minikube: `minikube start --cni=calico`.)

**Core mechanics — internalize these:**
- A policy selects pods via `podSelector` and applies to `Ingress`, `Egress`, or both (`policyTypes`).
- **Once a pod is selected by ANY policy for a direction, that direction becomes default-deny for it**,
  and only the listed rules are allowed. Pods with **no** policy remain open.
- **Rules are additive (whitelist/OR):** traffic is allowed if it matches *any* rule. You can't write a
  "deny" rule — you deny by *omission*.

**The three peer selectors (and a critical gotcha):**
```yaml
from:                       # (or 'to:' for egress)
  - podSelector: {...}      # pods in the SAME namespace
  - namespaceSelector: {...}# all pods in matching namespaces
  - ipBlock: {cidr: ...}    # external CIDRs
```
**Gotcha:** within a single `from` list entry, combining `podSelector` + `namespaceSelector` (no dash
between them) = AND (pods matching X *in* namespaces matching Y). As **separate list items** (each with
its own `-`) = OR. This distinction is a favorite exam trap.

**Default-deny-all-ingress (canonical snippet to memorize):**
```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata: {name: default-deny-ingress, namespace: web}
spec:
  podSelector: {}          # selects ALL pods in the namespace
  policyTypes: [Ingress]   # deny all ingress (no rules = nothing allowed)
```
Add `Egress` to `policyTypes` (with `egress: []`) for default-deny egress too.

**Allow example (only pods labeled role=frontend, on port 80):**
```yaml
spec:
  podSelector: {matchLabels: {app: api}}
  policyTypes: [Ingress]
  ingress:
    - from:
        - podSelector: {matchLabels: {role: frontend}}
      ports:
        - {protocol: TCP, port: 80}
```

**DNS gotcha:** a default-deny **egress** policy also blocks DNS (UDP/TCP 53 to CoreDNS) — remember to
allow egress to kube-system/CoreDNS or apps can't resolve names.

## Exam traps
- Policy has no effect → CNI doesn't enforce policy (use Calico).
- AND vs OR in the `from` block (dash placement) — read carefully.
- Empty `podSelector: {}` means **all** pods, not none.
- Forgetting to allow DNS egress under default-deny-egress.

## Socratic checks (model answers)
1. *A pod is selected by a policy but you listed no ingress rules — what's allowed in?* → nothing
   (default-deny for that direction).
2. *Two peers as separate `-` items vs combined under one item — semantics?* → separate = OR; combined
   podSelector+namespaceSelector = AND.
3. *Egress default-deny broke name resolution — why?* → DNS (port 53 to CoreDNS) is now blocked; allow it.
