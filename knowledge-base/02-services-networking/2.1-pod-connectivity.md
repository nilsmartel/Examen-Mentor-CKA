# 2.1 — Pod Connectivity & the Kubernetes Network Model

**Domain:** Services & Networking (20%) · **Lab:** `labs/lab-2.1-pod-connectivity.md`
**Prereqs:** basic pods. Foundational; teach before Services.

## Learning objectives
The student can: state the Kubernetes networking model's guarantees, and test pod-to-pod connectivity
by IP across nodes.

## Teaching notes

**The model (4 rules — the exam assumes you know these):**
1. Every **pod gets its own IP** (from the pod CIDR), unique cluster-wide.
2. **Pods can reach every other pod** directly by IP, **across nodes, without NAT**.
3. **Nodes can reach all pods** (and vice versa) without NAT.
4. A pod sees its own IP the same way others see it.

This flat network is provided by the **CNI** (see [[1.7-extension-interfaces-cni-csi-cri]]). Kubernetes
itself doesn't implement it — it delegates to the plugin.

**Inside a pod:** all containers share the same network namespace → same IP, and reach each other over
`localhost:<port>`. That's why two containers in one pod can't both bind the same port.

**Pod IPs are ephemeral.** A pod that dies and is recreated gets a **new IP**. That instability is
exactly why **Services** exist (stable virtual IP + DNS name in front of a changing set of pods) —
this motivates [[2.2-services-endpoints]].

**CIDRs to know:**
- **Pod CIDR** — pod IP pool (e.g. `10.244.0.0/16`), set at cluster init (`--pod-network-cidr`).
- **Service CIDR** — virtual IPs for Services (e.g. `10.96.0.0/12`); Service ClusterIPs are **not**
  real interfaces — kube-proxy/iptables/IPVS routes them to pod IPs.

**Testing connectivity (the skill):**
```bash
kubectl get pods -o wide                    # see pod IPs and their nodes
kubectl run a --image=nginx
kubectl run b --image=busybox -it --rm -- wget -qO- --timeout=3 http://<pod-a-ip>
```

## Exam traps
- Relying on a **pod IP** as if it were stable — use a Service instead.
- Two containers in one pod binding the same port — collision (shared netns).
- Assuming pod-to-pod works when the **CNI** is broken (it's the CNI's job, not core K8s).

## Socratic checks (model answers)
1. *Can pod A on node1 reach pod B on node2 directly by IP?* → yes, no NAT — that's rule 2 (CNI provides it).
2. *Why can't you rely on a pod's IP for a client?* → pod IPs change on restart; use a Service.
3. *Two containers in one pod — how do they talk, and what can't they do?* → over `localhost`; they
   can't both bind the same port.
