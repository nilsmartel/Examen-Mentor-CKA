# 2.2 — Services & Endpoints

**Domain:** Services & Networking (20%) · **Lab:** `labs/lab-2.2-services.md`
**Prereqs:** [[2.1-pod-connectivity]]. Central to [[5.5-services-networking-troubleshooting]].

## Learning objectives
The student can: create the four Service types, explain how a Service maps to pods via labels →
EndpointSlices, and choose the right type per scenario.

## Teaching notes

**A Service = stable virtual IP + DNS name + load balancing** over a dynamic set of pods selected by
**label selector**. The Service watches for pods matching its selector and populates its
**EndpointSlices** with their IP:port. kube-proxy programs iptables/IPVS so traffic to the ClusterIP is
DNAT'd to a backing pod.

**The chain (memorize):** `Service (selector) → matching Ready pods → EndpointSlice (pod IPs) → kube-proxy → pod`.
Empty EndpointSlice = the #1 bug (selector/label mismatch or pods not Ready).

**Four types:**
- **ClusterIP** (default) — internal-only virtual IP. Pod-to-pod/service-to-service.
- **NodePort** — ClusterIP **plus** opens a port (30000–32767) on **every node**; reachable at
  `<nodeIP>:<nodePort>`. Superset of ClusterIP.
- **LoadBalancer** — NodePort **plus** asks the cloud/provider for an external LB. On minikube use
  `minikube tunnel` to get an external IP.
- **ExternalName** — no proxying; returns a CNAME to an external DNS name (no selector, no endpoints).

**Ports (3 different numbers — a classic confusion):**
- `port` — the Service's own port (what clients connect to).
- `targetPort` — the **pod/container** port traffic is forwarded to (defaults to `port`).
- `nodePort` — the external node port (NodePort/LoadBalancer only).

**Headless Service** (`clusterIP: None`) — no virtual IP; DNS returns the **pod IPs directly**. Used by
StatefulSets for stable per-pod DNS. (Links to [[3.4-self-healing-primitives]].)

**Imperative:**
```bash
kubectl expose deploy web --port=80 --target-port=8080            # ClusterIP from a deployment
kubectl expose deploy web --type=NodePort --port=80
kubectl create svc clusterip web --tcp=80:8080
kubectl get endpoints web ; kubectl get endpointslices           # who's behind it
minikube service web --url                                        # reachable URL on minikube
```

## Exam traps
- **Empty endpoints** → selector ≠ pod labels, or pods failing readiness (excluded until Ready).
- `targetPort` ≠ container's actual listening port → refused.
- NodePort outside 30000–32767 → rejected.
- Expecting `LoadBalancer` to get an IP on bare minikube without `minikube tunnel`.

## Socratic checks (model answers)
1. *Service has no effect; first command?* → `kubectl get endpoints <svc>` — empty ⇒ selector/label/readiness.
2. *Difference between `port` and `targetPort`?* → `port` = the Service's port for clients; `targetPort`
   = the pod's port it forwards to.
3. *Which type is a superset of which?* → LoadBalancer ⊃ NodePort ⊃ ClusterIP.
