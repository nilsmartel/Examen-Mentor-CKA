# 2.3 — Ingress Controllers & Resources

**Domain:** Services & Networking (20%) · **Lab:** `labs/lab-2.3-ingress.md`
**Prereqs:** [[2.2-services-endpoints]].

## Learning objectives
The student can: deploy an ingress controller, write an Ingress that routes by host/path to Services,
and explain the controller-vs-resource split.

## Teaching notes

**Two separate things — the key distinction:**
- **Ingress resource** — the *rules* (host/path → Service:port). Just data; does nothing alone.
- **Ingress controller** — the *pod* (e.g. ingress-nginx) that watches Ingress resources and actually
  proxies HTTP(S) traffic. **No controller = your Ingress does nothing.**

On minikube: `minikube addons enable ingress` (installs ingress-nginx).

**An Ingress routes L7 (HTTP/HTTPS)** by host and path to backend Services (which then hit pods). It's
the standard way to expose many services under one external IP/port with name-based routing + TLS.

**Anatomy:**
```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: shop
  # annotations:                      # controller-specific behavior (rewrites, etc.)
  #   nginx.ingress.kubernetes.io/rewrite-target: /
spec:
  ingressClassName: nginx             # which controller handles this
  rules:
    - host: shop.example.com
      http:
        paths:
          - path: /api
            pathType: Prefix          # Prefix | Exact | ImplementationSpecific
            backend:
              service: {name: api-svc, port: {number: 80}}
          - path: /
            pathType: Prefix
            backend:
              service: {name: web-svc, port: {number: 80}}
  # tls:                              # HTTPS termination
  #   - hosts: [shop.example.com]
  #     secretName: shop-tls
```
`pathType` is **required**. `ingressClassName` selects the controller (or set a default IngressClass).

**Imperative:**
```bash
kubectl create ingress shop --class=nginx \
  --rule="shop.example.com/api=api-svc:80" \
  --rule="shop.example.com/*=web-svc:80"
```

**Testing on minikube:**
```bash
kubectl get ingress            # note the ADDRESS
curl --resolve shop.example.com:80:$(minikube ip) http://shop.example.com/   # fake the DNS
```

## Exam traps
- Writing an Ingress but no controller running → 404/nothing. Enable/verify the controller.
- Missing `pathType` (required in `networking.k8s.io/v1`).
- Backend Service name/port wrong, or the Service itself has no endpoints (debug the Service first).
- TLS `secretName` must be a `kubernetes.io/tls` secret with the right host.

## Socratic checks (model answers)
1. *You applied an Ingress and nothing happens — likely cause?* → no ingress **controller** running.
2. *Which field is mandatory in each rule path?* → `pathType`.
3. *Ingress vs Service — what layer does Ingress add?* → L7 host/path HTTP routing + TLS in front of Services.
