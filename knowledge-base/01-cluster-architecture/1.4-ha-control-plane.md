# 1.4 — Highly-Available Control Plane

**Domain:** Cluster Architecture (25%) · **Lab:** `labs/lab-1.4-ha-inspect.md`
**Prereqs:** [[1.2-kubeadm-install-prereqs]], [[1.5-etcd-backup-restore]].
**⚠️ Concept-heavy on minikube** — inspect topology & rehearse; can't stand up 3 CP nodes here.

## Learning objectives
The student can: explain stacked vs external etcd topologies, the role of the control-plane load
balancer, and how many nodes tolerate how many failures.

## Teaching notes

**Why HA:** a single control-plane node is a single point of failure. HA means ≥3 control-plane nodes
behind a **load balancer** on the API server port (6443), plus a resilient **etcd** cluster.

**Two topologies:**
- **Stacked etcd** (default kubeadm HA): each control-plane node also runs an etcd member. Simpler,
  fewer machines; but losing a node loses both an API server *and* an etcd member.
- **External etcd:** etcd runs on its own dedicated nodes, separate from the control plane. More
  resilient and independently scalable; more machines to manage.

**etcd quorum (raft):** etcd needs a **majority** to accept writes. With N members, quorum = ⌊N/2⌋+1,
tolerating ⌊(N-1)/2⌋ failures:
| etcd members | quorum | failures tolerated |
|:---:|:---:|:---:|
| 1 | 1 | 0 |
| 3 | 2 | 1 |
| 5 | 3 | 2 |
Use an **odd** number (3 or 5). Even numbers add a member without improving fault tolerance.

**The load balancer:** all `kubeadm join --control-plane` and all worker/kubectl traffic points at a
stable VIP/LB in front of the API servers. `--control-plane-endpoint=<lb>:6443` is set at init time
(you can't easily add HA later without this).

**Joining more control-plane nodes:**
```bash
sudo kubeadm join <lb>:6443 --token <t> --discovery-token-ca-cert-hash sha256:<hash> \
  --control-plane --certificate-key <key>
```
The `--certificate-key` (from `kubeadm init --upload-certs`) lets the new node fetch the shared certs.

## Exam traps
- Even-numbered etcd clusters (e.g. 2 or 4) — no better than the odd number below them, worse for quorum.
- Forgetting `--control-plane` / `--certificate-key` when joining an additional control-plane node
  (it would join as a worker).
- Not setting `--control-plane-endpoint` at init → can't cleanly add HA members later.

## Socratic checks (model answers)
1. *How many control-plane/etcd nodes to tolerate one failure?* → 3 (quorum 2).
2. *Stacked vs external etcd — one-line difference?* → stacked runs etcd on the control-plane nodes;
   external runs it on dedicated nodes.
3. *Why 3 or 5 and not 4?* → quorum needs a majority; 4 tolerates the same 1 failure as 3 but risks
   split-brain economics — always use odd numbers.
