# 1.7 — Extension Interfaces: CNI, CSI, CRI

**Domain:** Cluster Architecture (25%) · **Lab:** `labs/lab-1.7-interfaces-inspect.md`
**Prereqs:** [[1.2-kubeadm-install-prereqs]].

## Learning objectives
The student can: explain what each of the three interfaces plugs into, name where it's configured, and
inspect the active plugin on a node.

## Teaching notes

Kubernetes deliberately delegates three concerns to pluggable interfaces so vendors can implement them:

**CRI — Container Runtime Interface** (compute). How the kubelet talks to the container runtime
(containerd, CRI-O). The kubelet is a CRI *client*; the runtime is the server.
- Config: kubelet flag `--container-runtime-endpoint` (a unix socket, e.g.
  `unix:///run/containerd/containerd.sock`).
- Inspect: `crictl ps`, `crictl images`, `crictl info` on the node. `crictl` is the CRI-level `docker`.
- Note: Docker/`dockershim` was removed; runtimes are containerd/CRI-O now.

**CNI — Container Network Interface** (networking). Gives pods IPs and wires pod-to-pod connectivity;
some CNIs (Calico, Cilium) also enforce NetworkPolicy. Without a CNI, nodes stay `NotReady`.
- Config: CNI plugin binaries in `/opt/cni/bin/`, config in `/etc/cni/net.d/`.
- Inspect: `ls /etc/cni/net.d/`; the CNI usually runs as a DaemonSet in `kube-system`
  (`kubectl get pods -n kube-system` → calico-node/kindnet/cilium/flannel).
- Examples: Flannel (simple, no NetworkPolicy), Calico/Cilium (NetworkPolicy-capable).

**CSI — Container Storage Interface** (storage). How Kubernetes provisions/attaches/mounts external
storage via vendor drivers.
- Inspect: `kubectl get csidrivers`, `kubectl get csinodes`, `kubectl get storageclass`
  (the SC's `provisioner` is the CSI driver).
- Connects to [[4.3-storage-classes-dynamic-provisioning]].

**One-line each:** CRI = run containers; CNI = pod networking; CSI = pod storage.

## Exam traps
- Attributing `NotReady` nodes to the runtime when it's actually a **missing/broken CNI**.
- Confusing where things live: `/etc/cni/net.d` (CNI config) vs `/etc/kubernetes/manifests` (static pods).
- Expecting NetworkPolicy to work under a CNI that doesn't enforce it (e.g. plain Flannel).

## Socratic checks (model answers)
1. *Which interface, if missing, keeps nodes NotReady?* → CNI.
2. *How do you see the container runtime's containers on a node?* → `crictl ps` (CRI).
3. *Where does a StorageClass name its CSI driver?* → the `provisioner` field.
