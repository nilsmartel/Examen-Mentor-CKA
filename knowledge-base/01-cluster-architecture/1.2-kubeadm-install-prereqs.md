# 1.2 — kubeadm Install & Infrastructure Prerequisites

**Domain:** Cluster Architecture (25%) · **Lab:** `labs/lab-1.2-kubeadm-inspect.md`
**Prereqs:** [[1.7-extension-interfaces-cni-csi-cri]] (CNI/CRI context helps).
**⚠️ Concept-heavy on minikube** — you can't bootstrap a fresh multi-machine cluster here. Inspect the
existing kubeadm node and rehearse the command sequence.

## Learning objectives
The student can: describe the node prerequisites, and recite/explain the `kubeadm init` → CNI →
`kubeadm join` workflow, and where the join command/token come from.

## Teaching notes

**What kubeadm does:** bootstraps a conformant cluster by generating certs, writing the control-plane
static-pod manifests to `/etc/kubernetes/manifests/`, starting etcd + control plane, and setting up
the bootstrap tokens so workers can join. It does **not** install a CNI — you do that after init.

**Node prerequisites (per machine) — the setup that precedes `kubeadm init`:**
1. A **container runtime** implementing CRI (containerd/CRI-O). Configure its cgroup driver to
   **systemd** to match the kubelet.
2. **kubeadm, kubelet, kubectl** packages installed (matching minor version).
3. **Kernel/network prep:** load `br_netfilter`, set `net.bridge.bridge-nf-call-iptables=1` and
   `net.ipv4.ip_forward=1`. **Swap off** (`swapoff -a` + remove from fstab) for classic setups.
4. Required ports open (6443 API, 2379-2380 etcd, 10250 kubelet, 10259 scheduler, 10257 c-m).

**The bootstrap sequence (memorize the shape):**
```bash
# on the first control-plane node:
sudo kubeadm init --pod-network-cidr=10.244.0.0/16 --apiserver-advertise-address=<ip>
# set up kubectl for your user:
mkdir -p $HOME/.kube && sudo cp /etc/kubernetes/admin.conf $HOME/.kube/config && sudo chown $(id -u):$(id -g) $HOME/.kube/config
# install a CNI (e.g. Calico/Flannel) — nodes stay NotReady until this is done:
kubectl apply -f <cni-manifest>
# on each worker (kubeadm init printed this):
sudo kubeadm join <cp-ip>:6443 --token <t> --discovery-token-ca-cert-hash sha256:<hash>
```

**Tokens & join, if you lost the command:**
```bash
kubeadm token create --print-join-command      # regenerate the full join command
kubeadm token list
```
`--pod-network-cidr` must match what the CNI expects (e.g. Flannel wants `10.244.0.0/16`).

**Why nodes are `NotReady` right after init:** no CNI yet → `NetworkUnavailable`. Installing the CNI
flips them to `Ready`. (Connects to [[5.1-cluster-node-troubleshooting]].)

## Exam traps
- Forgetting to install a CNI → permanent `NotReady`.
- cgroup driver mismatch (kubelet vs runtime) → kubelet won't start.
- Wrong/expired token on join → regenerate with `kubeadm token create --print-join-command`.
- Swap left on (classic setups) → init/kubelet fails.

## Socratic checks (model answers)
1. *After `kubeadm init` all nodes are NotReady. Why?* → no CNI installed yet.
2. *You lost the worker join command. How do you get a new one?* →
   `kubeadm token create --print-join-command`.
3. *Which two things must match between the kubelet and the container runtime?* → the **cgroup driver**
   (systemd) and the Kubernetes minor version compatibility.
