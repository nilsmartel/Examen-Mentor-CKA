# 4.3 — StorageClasses & Dynamic Provisioning

**Domain:** Storage (10%) · **Lab:** `labs/lab-4.3-storageclass.md`
**Prereqs:** [[4.2-pv-pvc]], [[1.7-extension-interfaces-cni-csi-cri]] (CSI).

## Learning objectives
The student can: explain dynamic provisioning, use/identify the default StorageClass, and control
binding mode and reclaim policy via the class.

## Teaching notes

**Dynamic provisioning removes the manual PV step.** Instead of an admin pre-creating PVs, a
**StorageClass** describes *how* to provision storage on demand. When a PVC references a StorageClass
(or the **default** class), a PV is **created automatically** by the class's `provisioner` (a CSI
driver). No more Pending-waiting-for-a-matching-PV.

**StorageClass anatomy:**
```yaml
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata: {name: fast}
provisioner: k8s.io/minikube-hostpath      # the CSI/driver that creates volumes
reclaimPolicy: Delete                       # applied to dynamically created PVs
volumeBindingMode: WaitForFirstConsumer     # vs Immediate
allowVolumeExpansion: true
parameters: {type: pd-ssd}                   # driver-specific
```

**Two fields that matter on the exam:**
- **volumeBindingMode:**
  - `Immediate` — PV is provisioned as soon as the PVC is created.
  - `WaitForFirstConsumer` — wait until a **pod** using the PVC is scheduled, so the volume is created
    in the right zone/node (topology-aware). The PVC stays `Pending` until a consuming pod exists —
    **this is expected, not a bug** (common confusion).
- **reclaimPolicy** on the class → inherited by the PVs it creates (`Delete` default).

**The default StorageClass:**
```bash
kubectl get storageclass                    # the one marked (default)
kubectl get sc <name> -o yaml | grep is-default-class    # annotation storageclass.kubernetes.io/is-default-class
```
A PVC with **no** `storageClassName` uses the default class. On minikube, `standard` is default.

**End-to-end dynamic flow:** create SC (or use default) → create PVC referencing it → (a pod schedules,
if WaitForFirstConsumer) → PV auto-created and Bound.

## Exam traps
- PVC `Pending` with `WaitForFirstConsumer` is normal **until a pod consumes it** — don't chase a
  non-bug; schedule a pod.
- Omitting `storageClassName` uses the default class; `storageClassName: ""` disables dynamic
  provisioning (static only).
- Changing the default class = editing the `is-default-class` annotation (and unsetting the old one).

## Socratic checks (model answers)
1. *What creates the PV under dynamic provisioning?* → the StorageClass's `provisioner` (a CSI driver).
2. *PVC with `WaitForFirstConsumer` is Pending — bug or expected?* → expected until a pod using it is scheduled.
3. *A PVC has no `storageClassName` — what happens?* → it uses the cluster's default StorageClass.
