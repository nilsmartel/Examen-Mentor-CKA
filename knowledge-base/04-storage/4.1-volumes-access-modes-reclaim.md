# 4.1 — Volumes, Access Modes & Reclaim Policies

**Domain:** Storage (10%) · **Lab:** `labs/lab-4.1-volumes.md`
**Prereqs:** basic pods. Foundation for [[4.2-pv-pvc]].

## Learning objectives
The student can: distinguish ephemeral vs persistent volumes, and correctly read access modes and
reclaim policies.

## Teaching notes

**Ephemeral vs persistent — the fundamental split:**
- **emptyDir** — scratch space that lives and dies **with the pod**. Shared between containers in the
  pod. Gone when the pod is deleted. Good for caches / inter-container handoff.
- **hostPath** — mounts a path from the **node's** filesystem. Node-bound, not portable, risky in
  multi-node. Used in labs/system pods.
- **PersistentVolume (PV)** — storage whose lifecycle is **independent of any pod**; survives pod
  deletion. Consumed via a PVC (see [[4.2-pv-pvc]]).
- **ConfigMap/Secret volumes** — config injected as files (see [[3.2-configmaps-secrets]]).

**Access modes (who can mount, how) — know the abbreviations:**
- **RWO** `ReadWriteOnce` — mounted read-write by a **single node** (most block storage).
- **ROX** `ReadOnlyMany` — read-only by many nodes.
- **RWX** `ReadWriteMany` — read-write by many nodes (needs NFS/CephFS-type backends).
- **RWOP** `ReadWriteOncePod` — read-write by a single **pod** (stricter than RWO).
Access mode is a *matching* attribute between PV and PVC; the mode doesn't *enforce* on its own — it's
what the binding uses to pair them.

**Reclaim policy (what happens to the PV when its PVC is deleted):**
- **Retain** — keep the PV and its data; admin must clean up manually (PV goes to `Released`, not
  reusable until manually reset). Safest for important data.
- **Delete** — delete the PV **and** the underlying storage asset. Common default for dynamically
  provisioned volumes.
- (`Recycle` is deprecated — don't teach it as current.)

**volumeMode:** `Filesystem` (default) vs `Block` (raw block device).

## Exam traps
- Expecting `emptyDir`/`hostPath` data to survive pod deletion — it won't (that's what PVs are for).
- Access-mode mismatch between PVC request and available PV → PVC stays **Pending**.
- Assuming `RWX` works on any backend — it needs a shared filesystem provider.
- Reclaim `Retain` leaves a `Released` PV that won't auto-rebind — surprises people.

## Socratic checks (model answers)
1. *Pod using emptyDir is deleted — what happens to the data?* → gone; emptyDir is pod-scoped.
2. *RWO vs RWX?* → RWO = one node read-write; RWX = many nodes read-write (needs shared storage).
3. *Reclaim `Retain` vs `Delete` when the PVC is deleted?* → Retain keeps the PV/data (manual cleanup);
   Delete removes the PV and the backing storage.
