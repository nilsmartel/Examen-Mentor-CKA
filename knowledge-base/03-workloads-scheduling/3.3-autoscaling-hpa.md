# 3.3 — Workload Autoscaling (HPA)

**Domain:** Workloads & Scheduling (15%) · **Lab:** `labs/lab-3.3-hpa.md`
**Prereqs:** [[3.1-deployments-rollouts]], [[5.3-resource-usage-monitoring]] (metrics-server required).

## Learning objectives
The student can: create an HPA targeting CPU, explain what it needs to work, and interpret its status.

## Teaching notes

**HPA scales the number of replicas** of a Deployment/ReplicaSet/StatefulSet based on observed metrics
(commonly CPU/memory). It **requires metrics-server** (the metrics.k8s.io API) — no metrics-server, no
HPA. And it **requires resource `requests`** on the pods, because CPU utilization is measured *relative
to the request*.

**The math:** `desiredReplicas = ceil(currentReplicas × currentMetric / targetMetric)`.
Target CPU 50% with pods at 100% of their request → roughly doubles replicas (bounded by min/max).

**Create it:**
```bash
kubectl autoscale deploy web --cpu-percent=50 --min=1 --max=10
kubectl get hpa                      # TARGETS shows current%/target%
kubectl describe hpa web             # events + scaling decisions
```
YAML (autoscaling/v2 supports multiple metrics):
```yaml
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata: {name: web}
spec:
  scaleTargetRef: {apiVersion: apps/v1, kind: Deployment, name: web}
  minReplicas: 1
  maxReplicas: 10
  metrics:
    - type: Resource
      resource: {name: cpu, target: {type: Utilization, averageUtilization: 50}}
```

**Prereqs checklist to teach:** (1) metrics-server running, (2) pods have CPU `requests`, (3) the
target workload exists. Miss any → HPA shows `<unknown>` in TARGETS and won't scale.

**vs VPA / Cluster Autoscaler (one line each):** HPA = more/fewer pods; VPA = bigger/smaller pods
(right-sizing requests); Cluster Autoscaler = more/fewer nodes. CKA cares about **HPA**.

## Exam traps
- HPA `TARGETS: <unknown>` → metrics-server missing OR pods lack CPU **requests**.
- Expecting instant scaling — there's a stabilization window; scale-down is deliberately slow.
- Also running a manual `kubectl scale` on an HPA-managed deployment (they fight).

## Socratic checks (model answers)
1. *HPA shows `<unknown>` utilization — two possible causes?* → no metrics-server, or pods have no CPU request.
2. *What does HPA change vs the Cluster Autoscaler?* → HPA changes replica count; CA changes node count.
3. *Create an HPA imperatively for deploy `web`, 50% CPU, 1–10?* →
   `kubectl autoscale deploy web --cpu-percent=50 --min=1 --max=10`.
